## 2026-09-17

### Completed

- Closed the BRAWUKA-310 gap left by the viewer's session cache: the one-decrypted-document buffer now also drops when the viewer closes. The renderer calls the new `close_source_document_view` command from both close paths the `View document` action opens — the PDF/image pixel viewer and the CSV preview, which the same one-entry buffer backs — so a decryption no longer waits for the next viewed document, the Vault lock, or a deletion. The command is idempotent and Vault-lock independent, because the lock path drops the buffer itself and closing a viewer afterwards must stay a no-op, and an empty document id is refused as `invalid_document_request`; a failed release is reported like any other command unless the Vault session it belonged to already ended, so the lock-path reset stays quiet. `runtime/documents.rs` stays inside its size ratchet by keeping the command and the cache release it drives together in `runtime/document_cache.rs`.
- Spec 0017 names the trigger in the source-file access rules and in the acceptance criteria as the renderer's viewer-close signal, so the drop list is not read as a plaintext-lifetime guarantee for a destroyed webview: closing the main window never runs the renderer's close handler, and the retained process clears that buffer only on Vault lock or quit (spec 0009).
- Landed the persistent operational log and the two-layer error model of spec 0015 (BRAWUKA-293, `feat/operational-log-error-model`). Migration `0014_operational_logs.sql` adds a local-only `operational_logs` table whose columns are the spec's whitelist — timestamp, static error code, job type, job status, attempt, duration, app version, and the sanitized component — plus one already-rendered technical `detail` line; there is no free-form column a caller can stuff a payload into. `src/diagnostics.rs` owns the redaction (`redact`/`RedactedText`, a whitelist of shape-preserving patterns) and the renderers for the preview and the export.
- Every job-failure writer now stores the technical layer. `fail_reconcile_document`, `fail_parse_document_job`, and `fail_review_batch` build `error_json` from the job row's own run context (`provider`, `jobType`, `attempt`, `maxAttempts`, `retryable`, related ids) plus a `JobFailureDetail { component, reason }`, and fall back to the bare `{"errorCode": ...}` payload when the job context cannot be read — a job that cannot be read back is still marked failed. User-facing codes, `blocked_reason`, retry accounting, and the claim/lease SQL are unchanged.
- The financial store steps that used to discard their `StoreResult` error into a static code now record it first. `runtime::error::StoreResultExt::map_store_error` logs through the caller's store handle (the same unlock/standby state is preserved), and the store is never re-locked to log, so a held guard cannot deadlock itself. All store steps whose error was collapsed with `map_err(|_| ...)` were migrated — `runtime/review.rs`, `documents.rs`, `inbox.rs`, `documents_intake.rs`, `inbox_intake.rs`, and the rest; the wrappers stay best-effort: the renderer still receives exactly the code it received before.
- Retention and export are host-owned. `purge_expired_operational_logs` runs on every Vault open (30-day window) and `operational_diagnostics_export` writes only from a previewed, redacted read, states the retention window and truncation in the file, and refuses a destination it cannot write. Both commands are exposed to the renderer (`operational_diagnostics_preview`, `save_operational_diagnostics`) through the generated wire types, so the Settings surface that consumes them is a renderer-only follow-up.
- The three files that the guardrail ratchets — `database/mod.rs`, `runtime/documents.rs`, `runtime/review.rs` — were split rather than grown: `database/job_failures.rs`, `database/operational_logs.rs`, `runtime/review_jobs.rs`, and `runtime/statement_passwords.rs` now own the job-failure writers, the log storage/preview/export, the review-batch job flow, and the statement-password lifecycle. `pnpm check:file-size` passes with all four under the guardrail.
- Gates after the review round: `cargo test --locked` (240 passed, 1 ignored), `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `pnpm check:presentation-types`, `pnpm verify:fast` (file-size, ui-discipline, typecheck, `test:unit` 368 passed, build:web, website build+check) — pass. `pnpm verify`'s native half stops at `build:sidecar` in this environment because the local Node build has Node SEA disabled; the Rust gates were run directly with `--locked`.

- Review round on PR 148: the technical layer is no longer a restatement of the static code. `RuntimeError` carries an optional `JobFailureDetail`; `store_failure`/`runtime_failure` fill it from the real error, and the job writers take `error.detail_or_code(provider)` instead of synthesizing one from the code. `retryable` follows the error class (`io`/`sqlite`/transport true, deterministic protocol and validation failures false), and a test pins both the persisted `error_json.technical` fields and the log entry's reason.
- The non-store write paths now record their error too: statement-password and Gmail refresh-token keychain save/load/delete, `plan.read()`, `write_export_atomically`, the Inbox `read_dir`, and the Vault lifecycle recovery-status and directory steps all record through `runtime_failure`, or, where the caller already holds the store guard, through the guard itself. Pure validation rejections and `JoinError`s stay silent.
- Fixed the deadlock that coverage exposed: `runtime_failure` takes the store lock to append its entry, so calling it from a scope that already holds the store guard froze the whole app — eight test threads hung inside the statement-password, Gmail, remembered-key, and recovery paths. Store steps log through the guard they hold (`store_failure`), scopes that hold the guard without a store instance (`create`, `unlock`, `unlock_with_keychain`, `remember_on_this_mac`, `save_recovery_file`) hand their detail to `log_released_failure` after releasing it, and `VaultRuntime::store` now records itself on a thread-local so `runtime_failure` fails loudly in tests (`debug_assert`) instead of hanging. The suite that hung now finishes in 52 s.
- The sidecar transport was decomposed instead of grown: `runtime/sidecar_failure.rs` owns the failure record (`SidecarExchange`, `stderr_tail`), and one `run_sidecar_exchange` replaces the two near-identical protocol loops, so every exit — timeout, exit status, stderr tail, protocol violation, reported code — names its actual cause instead of `normalizer_failed`. `runtime/sidecar.rs` drops from 1083 to 781 lines and no longer needs a guardrail exemption; the shared keychain fakes moved from `runtime/tests.rs` (ratchet lowered 3587 → 3490) into `runtime/test_support.rs`, and the intake metadata helpers into `runtime/documents_intake.rs`.
